# eval-dataset-design

一套 AI 模型评测集设计的结构化方法论。输入项目背景信息，输出可直接交给标注团队执行的完整评测方案——包括构建原则、评测维度、打分规则和 case 样例。

> 不是理论框架，是可以直接用的流程。每一步都有输入/输出/自检，踩过的坑都列在常见错误表里。

---

## 解决什么问题

做过评测集的人大概率遇到过这三个坑：

**坑一：构建原则和评测维度搞混**
> "我们选了冷门库的代码来测" —— 这是数据集长什么样（构建原则），不是考察模型什么能力（评测维度）。混在一起会导致维度定义模糊，标注员不知道在评什么。

**坑二：打分靠标注员主观判断**
> "部分正确给一半分" "基本满足算过" —— 每个标注员对"部分"和"基本"的理解不同，标注一致性直接崩掉。

**坑三：难度分档没有标准**
> Hard 的定义是"比较难的题" —— 这等于没定义。出题人觉得难的，标注员可能觉得简单。

这个框架用六步流程系统性地解决这三个问题。

## 安装使用

这是一个 [Claude Code](https://docs.anthropic.com/claude-code) Skill 文件。

### 全局安装（推荐）

```bash
mkdir -p ~/.claude/skills
cp SKILL.md ~/.claude/skills/eval-dataset-design.md
```

安装后重启 Claude Code，输入 `/eval-dataset-design` 即可使用。

### 项目级安装

```bash
mkdir -p <your-project>/.claude/skills
cp SKILL.md <your-project>/.claude/skills/eval-dataset-design.md
```

### 使用示例

**示例 1：完整评测集设计**

```
/eval-dataset-design

我要评测多模态大模型的图片生成能力。
被评测对象：GPT-4o / Sora / MidJourney / 可灵 / 即梦
数据来源：韩国首尔真实外卖订单的菜品照片，2025年1-6月，500题
用途：内部模型选型
难点：韩餐/中餐/西餐的"好看"标准不一样
```

**示例 2：已有维度但需要补充打分规则**

```
/eval-dataset-design

我已经有 4 个评测维度，但打分标准太模糊，标注一致性差。
维度是：准确性、完整性、相关性、可读性。
帮我设计可操作的打分规则。
```

**示例 3：从已有 case 反推框架**

```
/eval-dataset-design

我有 20 道已标注的 case，想反推出系统化的评测框架。
把 case 发给框架分析。
```

## 工作流程

```
输入：项目背景信息
  │
  ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  收集信息    │ ──▶ │  构建原则    │ ──▶ │  一级维度    │
│  确认缺口    │     │  三个原则    │     │  4~6 个维度  │
└─────────────┘     └─────────────┘     └─────────────┘
                                               │
                                               ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Case 样例   │ ◀── │  打分规则    │ ◀── │  二级维度    │
│  5~8 道题    │     │  可执行模板  │     │  拆分+标准   │
└─────────────┘     └─────────────┘     └─────────────┘
       │
       ▼
 输出：完整评测方案
```

六步各自独立，每步格式统一：**需要什么 → 做什么 → 自检**。

## 核心设计理念

### 两层分离

| 层次 | 关注点 | 典型问题 |
|------|--------|----------|
| 构建原则 | 数据质量 | 选什么数据？覆盖什么范围？ |
| 评测维度 | 评分标准 | 用什么维度打分？每个维度怎么判？ |

### 四层递进维度

```
感知层   → 读没读对？      模型能不能读准输入信息
理解层   → 问没问对？      模型能不能理解用户意图
执行层   → 条件全满足？    模型能不能按要求完成任务
可信度层 → 知不知道不确定？ 模型知不知道自己的推断边界
```

### 打分可操作化

| 层次 | 打分方式 | 核心原则 |
|------|----------|----------|
| 感知层 | 信息点逐条核查 | 可数的，不靠判断 |
| 理解层 | 0/1/2 三档 | 有明确的分档边界 |
| 执行层 | 约束逐条核查 | 区分硬约束和软约束 |
| 可信度层 | 仅信息缺失题打分 | 有明确的 0 分信号 |
